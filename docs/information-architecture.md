# Information architecture

## Homepage

1. **Introduction** — name, truthful positioning, availability, portrait slot.
2. **Technical range** — the five-waypoint line and a concise explanation.
3. **Selected work** — ETS Website, Sentinel, Snakinesis, RideFlow, DataPulse, Financial Tick Data Pipeline.
4. **Experience** — Eastern Testing Services internship with dates and non-quantified responsibilities.
5. **Approach** — problem framing, architecture, AI-assisted implementation, verification.
6. **Foundation** — degree, expected graduation, CGPA, selected coursework.
7. **Contact** — email, GitHub, LinkedIn; Instagram secondary. Phone omitted from the primary public surface.

## Dedicated routes

- `/work/ets-website` — representative flagship case-study layout, explicitly sanitized and marked in development.
- `/work/sentinel`
- `/work/snakinesis`
- `/work/datapulse`
- `/work/financial-tick-pipeline`

The initial implementation may fully write only one representative case study while keeping all route content in a shared model.

## Progressive disclosure

- Homepage: problem, role/status, system span, short proof.
- Case study: context, constraints, architecture, decisions, evidence, limits, next steps.
- Private projects: abstract diagrams and approved descriptions only; no source, sensitive data, internal records, or security-sensitive detail.
- Collaborative projects: no final authorship language until contribution splits are confirmed.

## Exclusions

- Academic year/semester until resolved.
- Matootoo.
- Toy assignments.
- Unverified metrics and deployment claims.
- A primary phone-number CTA.
